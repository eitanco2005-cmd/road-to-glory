# R6B: Conversion readiness for the wedding products (branch `ws/convert`)

Goal: a new, unknown shop needs trust and a way to try before buying, before Google starts sending visitors.
No fake reviews, no fake scarcity, no countdowns. Everything is generated by one idempotent script, so it can be re-run
after merges: `python3 tools/convert/build_convert.py` (also called from `tools/site/build_site.py`).

## What was built

### 1. Free samples (direct download: no payment, no email, no sign-up), in `docs/samples/`
| File | What it is | Built by |
|---|---|---|
| `mini-wedding-budget.xlsx` | 1 RTL sheet, ~45 real formulas (guests × plate, totals, balance, over-plan in red, gift estimate, net cost), yellow input cells with validation, branded header, hyperlink to the full planner (`?utm_source=sample`) | `tools/convert/make_mini_budget.py` (openpyxl; recalculated with LibreOffice to check) |
| `seating-chart-sample.pdf` | Clean PDF from the seating app's real export (the demo event, 77 made-up guests, 8 tables + A–Z escort list), with a dashed "sample, made-up names" banner | `tools/convert/samples.js` (Playwright) |
| `invitation-sample.png` | Clean 1200px invitation ("ענפי זית", Hebrew date), the default made-up names | `tools/convert/samples.js` |

Previews (`docs/samples/img/*.webp`) are rendered from the real files. They appear as "נסו בחינם" cards on the product pages,
in a new hub section `chatuna/#dugmaot`, and on the bundle page.

### 2. Product pages (`p/wedding-planner`, `p/seating-chart`, `p/invitation-maker`, new `p/rsvp-tracker`)
A "before you buy" block (`#before-buy`, between `<!-- convert:trust -->` markers, right after the hero) with:
"מה מקבלים ב-₪X" checklist · "למי זה מתאים" + "ולמי פחות" (honest limits, e.g. no photo upload in invitations,
seating isn't a scale floor plan, RSVP is self-service, not a call centre) · free sample card · "איך זה עובד" 3 steps
(file products: pay → download → fill; apps: use free → unlock → export) · trust row: secure payment (PayPal or card,
no PayPal account, we don't see card details), instant delivery explained per product, honest refund line + link to
`legal/refund/` (matches the policy: no cancel for a change of mind; full refund if broken / not as described and not fixed).

- **New `p/rsvp-tracker/`**: the RSVP app had no landing page (its catalog card pointed straight to the app). Now it has one:
  2 screenshots rendered at 2x (desktop + phone), buy box, FAQ, JSON-LD. `docs/data/products/rsvp-tracker.json` `page` now
  points to it (+ `image` for the catalog card).
- Existing screenshots were kept (already real renders). New screenshots/previews are at deviceScaleFactor 2.

### 3. Funnel
- **Gift calculator** (`tools/wedding-gift/`): a gentle "מתחתנים בעצמכם?" box after the result + share button, linking to
  `chatuna/#mitchatnim`. `build_embeds.py` drops it (`COMMON_DROP`), so the third-party embed stays clean.
- **RSVP 80 limit**: the limit banner adds "או כל 4 כלי החתונה ב-₪79 (הכי משתלם)"; the unlock dialog now offers two
  choices: "רק הכלי הזה" (pre-selected) and "חבילת החתונה · הכי משתלם" (₪79 vs ₪126, live from the JSON). Choosing the bundle
  swaps the buy box and explains that after paying you land on a page with all four tools and your list stays saved.
- **Seating watermark export**: after the free watermarked PDF, a non-blocking note explains the watermark, offers the clean
  PDF + Excel + cards (₪29) and "כל 4 הכלים בחבילה · הכי משתלם", and can be dismissed ("לא עכשיו").
- The bundle choice lives in `apps/shared/unlock.js`, so it appears in every unlock dialog of the Hebrew seating/RSVP apps;
  English apps are unaffected (tested). The invitation maker uses its own buy box (not `AppUnlock`), so it was left as is.

### 4. Bundle page `p/wedding-bundle/` (new)
Compare table (4 rows: what it is, how you get it, separate price, ✓) with total ₪126 → ₪79 (save ₪47, 37%), screenshots
of all four tools, the 3 samples, fit / not fit (incl. "if you need only one tool, buy it alone"), steps + trust row, FAQ,
one buy box (the sticky bar and bottom button jump to it). Explicit line: "אין כאן מבצע מוגבל בזמן". All site links to the
bundle (`link_wedding.py` "next step" strips, hub samples) now go here instead of `chatuna/#bundle`.

### 5. Checkout copy
- PayPal item name stays the Hebrew product title (they were already clear); the order **description** is now
  "<title> · מוצר דיגיטלי מתכנון פלוס" (≤127 chars; English pages: "· digital product from Tichnun Plus").
- Thanks page: new "מה עכשיו?" list for wedding purchases (open the planner settings first / open each unlocked app /
  timeline + hub / keep this link for other devices), next to the existing "צריכים עזרה?" (email + order number + refund policy).

## Decisions
- One script owns all inserted regions (marker comments), so ws/quality text edits elsewhere on the same pages merge cleanly.
  The only edits outside my own files: `site.css` (appended block at the end), `unlock.js` (+bundle choice, +nudge),
  `seating/app.js` (print action), `rsvp/app.js` (limit banner line), `checkout.js` (description), `thanks/index.html`
  (next steps), `link_wedding.py` (bundle URL), `build_site.py` (+3 lines), `build_embeds.py` (1 drop pattern), `rsvp-tracker.json` (page/image).
- Single product stays pre-selected in the unlock dialog; the bundle is labelled best value but not forced.
- Bundle bought from inside an app redirects to the thanks page (existing bundle flow), which unlocks all three apps in that
  browser; the app data is in localStorage so nothing is lost. Noted in the dialog.
- Samples are clean (no watermark) on purpose so people judge real quality; fake names, plus a "sample" banner on the PDF.
