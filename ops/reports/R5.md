## What's built
- **Hub** `docs/chatuna/mechirim/` ("מחירון ספקים לחתונה 2026"). It has a one-table summary of all 10 vendors (low / typical / high), a budget box that uses the calculator's own default total, cards linking to each page, a "how we built it" section, an FAQ and WhatsApp share.
- **10 pages** under `docs/chatuna/mechirim/<slug>/`:

- **What every page has:**
  - Price table with low / typical / high columns. Each row has numbered references to a dated source list at the bottom.
  - A "how strong is this data" callout.
  - Sections: what drives the price, questions to ask the vendor, how to save.
  - "How this fits your budget" box. It is computed from the calculator's real vendor lines, parsed from `calc.js`, so it can't drift. It links to `tools/wedding-cost/`; the transport page uses the preset `#c&use_transport=1`. It also links the planner and the ₪79 bundle.
  - FAQ, related guides, sibling price pages.
  - WhatsApp share via `share.js`. It shares the page URL; there are no inputs.
- **JSON-LD:** Article + BreadcrumbList + FAQPage on all 11 pages. The FAQPage entries match the visible FAQ, and the test checks this.
- **OG image:** `docs/assets/og/wedding-prices.png`, added to `make_og.js`.
- **Generator:** `tools/wedding/build_price_pages.py` (content + SOURCES) and `price_render.py` (template). Running `build_site.py` calls the generator.
- **Bidi fix:** numeric ranges are wrapped in `<bdi dir=ltr>`, so "340–430" isn't displayed as "430–340" in RTL text.
  - Note: the older pages (kama-lasim, wedding-cost) probably have the same reversed-range issue. I didn't touch them because that was out of scope.

  - Each page states where data is thin.
- **Left out on purpose (no reliable current data), and the pages say so:** bridal bouquet, Tzohar / secular / Reform officiant / chazan fees, ketubah, groom-suit rental, LED screen, night-return surcharge, hair-only beyond one undated list.
- **Rabbi fees:** the only source is from 2019, and the page labels them "נתון 2019".

## Calculator model: not changed (decision)
I checked each `calc.js` vendor line (save / mid / premium) against the researched ranges. All lines are consistent:
- photo 6.5k / 10k / 16k
- DJ 4k / 7k / 12k
- dress 2.5k / 8k / 18k
- suit 1.5k / 2.5k / 5k
- makeup 1.5k / 3k / 5k
- decor 2k / 6k / 15k
- rabbi 1.5k / 2.5k / 4k (₪844 fee + officiant + ketubah)
- invitations / RSVP / magnets 1k / 3k / 7k
- transport 1.5k / 3k / 6k

The plate model is also consistent: center summer 480 sits inside 420–550, winter 385 inside 340–430, Thursday +12%.

Changing any line would ripple into the cost page's scenario table, FAQ, OG image, hub copy and e2e (₪185,000), with no accuracy gain, so I left it alone. Magnets stay inside the "invite" line, and the magnets page says so.
